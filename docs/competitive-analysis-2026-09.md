## 1. Что продукт есть на самом деле (сверено с диском, 19.09.2026)

**Strata** — многотенантная SaaS HR-платформа (HRIS + время + деньги + коммуникации) на Next.js 16 / React 19 / Convex, с армянской спецификой и 4 локалями.

| Параметр         | Значение                                       | Комментарий                                      |
| ---------------- | ---------------------------------------------- | ------------------------------------------------ |
| Роутов-страниц   | **152**                                        | из них ~50 модулей в `(dashboard)`               |
| Backend Convex   | **328 файлов**                                 | зрелая доменная модель, не монолит               |
| Frontend         | **~1600 файлов**                               |                                                  |
| Биллинг-каталог  | **58 модулей** (`billing/modules.ts`)          | единый реестр; редактор тарифов строится из него |
| Языки            | EN / RU / HY / DE                              | паритет ключей проверяется в CI                  |
| Роли             | 5: superadmin/admin/supervisor/employee/driver |                                                  |
| Тесты            | 656 файлов                                     | порог покрытия ~68%                              |
| Налоговый движок | **6 стран** (`lib/taxRules.ts`)                | Армения — точно, остальные approximate           |

### 1.1. Модули, которые реально есть

**Кадры:** сотрудники, департаменты, должности, орг. структура (React Flow), профили, испытательный срок, команды.
**Время:** посещаемость (распознавание лиц в браузере), учёт времени, отпуска/отгулы, календарь, переработки, графики смен, переговорные, видеоконференции (LiveKit).
**Талант:** подбор (ATS + публичный `/careers`), онбординг, оффбординг, обучение (LMS), найм-пакеты, преемственность (9-box), карьерные треки (skill matrix, gap-анализ).
**Эффективность:** performance/360, OKR/цели, strategy maps, признание, rewards, опросы/eNPS.
**Финансы:** зарплата, компенсации (грейды/бонусы), расходы (политики/лимиты), бенефиты, активы, отчёты, аналитика.
**Коммуникации:** чат, новости, approvals, рассылки, тикеты поддержки.
**Документы:** библиотека, версии, e-подписи (canvas + аудит + PDF), конструктор документов.
**Платформа:** публичный API v1 + вебхуки, SSO (SAML/OIDC), SCIM, TOTP, passkeys, аудит-лог, GDPR-инструментарий, бэкапы, автоматизация, Telegram, супер-админ (планы, фича-тумблеры, импersonation, экстренные инструменты, сборщик SOC 2-доказательств).
**AI:** ассистент, AI-оценщик, AI-рекрутинг (описание вакансии, подготовка к интервью, скоринг скрининга), прогноз оттока, AI-редактор сайта, модуль AI-Governance.

### 1.2. Армянский комплаенс — чем он на самом деле является

`convex/lib/taxRules.ts` — не «ставка НДФЛ в константе», а расширяемый движок правил:

- **Армения (точно, сверено с публикациями SRC/KGD):** плоский НДФЛ **20%** (НК РА, ст. 141); накопительная пенсия **5%/10%** по порогам с привязкой к году рождения и флагом `pensionExemptible`; военный сбор — фиксированные **1 000 / 15 000 AMD**; медстрахование — фиксированные суммы по брутто-порогам (**0 / 4 800 / …**).
- **Другие юрисдикции (approximate):** Россия (13/15% + соц. 2.9% + пенс. 22% + мед. 5.1%), Германия, Великобритания, Польша, США (федеральный).
- **Организация может переопределить правила** (`TaxRuleOverride`) без изменения кода. Добавление страны = одна запись в `TAX_RULES`.

Это существенно глубже того, что публично заявляет любой армянский вендор, и это же — готовый мостик в CIS (Россия/Польша уже есть в движке).

### 1.3. Плюсы архитектуры

- **Мультитенантность с серверным enforcement тарифов** — модули блокируются на сервере (`assertModuleAccess`), а не только в UI. У локальных конкурентов об этом публично не заявлено.
- **Enterprise-каркас:** RBAC + аудит + SSO + SCIM + passkeys + GDPR + бэкапы + публичный API. Это то, что покупает банк или телеком — при условии сертификатов.
- **i18n с CI-паритетом**, SEO-страницы `/compare/[vendor]` в 4 языках, k6-тесты производительности, Sentry/OTel, границы бандла.
- **Операционная зрелость:** редактор тарифов с живым предпросмотром лендинга, фича-тумблеры, импersonation, экстренные инциденты, time-boxed доступы для аудиторов.

### 2.2. Глобальные (в battlecards)

Personio, BambooHR, HiBob, Rippling, Leapsome, Deel — западные заводятся в армянские офисы МНК через головной офис. Против них мы играем **локальный слой**, а не замену.

### 2.3. Реальный конкурент — комбинация, а не один вендор

Клиент в Ереване почти никогда не выбирает между двумя HRIS. Он выбирает между **Strata** и **связкой** «Armsoft (зарплата) + Staff.am (найм) + OnTime (посещаемость) + Excel (отпуска) + Telegram (коммуникации)». Продавать нужно **консолидацию**, считая число подписок и объём ручной работы вслух.

**Про что это говорит:**

- **Против глобалов мы в 2–3 раза дешевле и включаем армянскую зарплату** — BambooHR/HiBob/Odoo за 50 человек стоят $500–1 250/мес до аддонов; у нас Pro на 50 местах — **$350**.
- **Против PeopleForce мы дороже в 2–3 раза** ($350 против $125 за 50 человек). Это реальный риск в русскоязычных CIS-сделках; наш ответ — не скидка, а локальный комплаенс, платежные рельсы и армянский интерфейс, которых у них нет.
- **Против локальных (Hirebee, List Work, Resalt, Spark.work) публичных цен почти нет** — quote-based. Это значит: **мы не должны заходить с ценой в разговор первыми**, потому что не знаем поля. Заходить глубиной (комплаенс, платформа, e-sign, API) и считать консолидацию.

## 5. Где мы сильны (moat)

1. **Глубина армянского комплаенса** — не ставка, а движок правил: ст. 141, накопительная пенсия с привязкой к году рождения, военный сбор, медстрахование по порогам, переопределение организацией. Ни один армянский вендор публично столько не заявляет.
2. **Мультистрановая налоговая база** — Россия/Германия/UK/Польша/USA уже в движке → реальный путь в CIS и для МНК-офисов.
3. **Платёжные рельсы** — Stripe + Idram/ArCa внутри продукта (мультитенантный биллинг). Локальные конкуренты так не продают подписки.
4. **Enterprise-каркас** — SSO SAML/OIDC, SCIM, passkeys/TOTP, аудит, GDPR-тулкит, публичный API v1 + вебхуки, бэкапы. Публично ни у одного армянского вендора этого нет.
5. **Широта** — 58 модулей против ~8–9 «зон» у локальных: assets, benefits, expenses, e-sign, compliance, video, переговорные, чат, проекты, преемственность, карьерные треки, водители.
6. **Серверный enforcement тарифов + редактор с живым предпросмотром** — операционная зрелость уровня не стартапа.
7. **Финансовая «последняя миля» и железо (с 19.09):** реестр банковских перечислений с реквизитами сотрудника и фильтрацией неплатёжеспособных строк, плюс приём протокола ZKTeco ADMS — терминал с КПП можно направить прямо на продукт. У локальных конкурентов это есть (Armsoft, OnTime), у глобалов — нет и не будет. **Довод для продажи, которого нет ни у кого:** формат файла не надо согласовывать с нами — бухгалтер загружает присланный банком шаблон, видит колонки и порядок до сохранения, а на экране сразу видно, у кого в этом месяце не хватает счёта.
8. **AI внутри продукта + AI-Governance** — Spark.work/Resalt/Hirebee заявляют AI, но governance-модуля нет ни у кого.
9. **4 языка, включая немецкий** — уникальная позиция для армянских офисов немецких групп (территория Personio).
10. **Честная публичная таблица** с проигрышными строками — доверие как оружие.

## 7. Рекомендации

### P0 — закрыть то, что блокирует сделки (0–3 мес.)

1. **Мобильный клиент.** Решение: React Native/Expo с общей доменной логикой; PWA остаётся как «нулевая установка», но не как ответ на «у вас есть приложение?». Минимальный объём для продажи: отметка прихода/ухода, отпуска, расписание смен, расчётный лист, push-уведомления, одобрение заявок. **Почему P0:** это единственный gap, который есть у **всех** локальных конкурентов сразу.
2. **Правовая база под биометрию** — согласие при зачислении, политика хранения дескрипторов, удаление при оффбординге, DPA с субпроцессорами. Без этого лицо-киоск — риск, а не фича.
3. ~~**«Последняя миля» зарплаты**~~ — **СДЕЛАНО 19.09:** реестр перечислений (XLSX + CSV), реквизиты счёта в профиле, неплатёжеспособные строки исключаются и перечисляются как проблемы. **Добавлено:** профили банковских файлов (`src/lib/payroll/bankProfile.ts`) — нейтральный формат плюс пресеты Ameriabank/ACBA/Ardshinbank/Fast Bank с настраиваемым порядком колонок, выбором в UI и предупреждением о непроверенном формате в интерфейсе и в каждом экспорте. **Осознанно:** пресеты помечены `verified: false` — мы не выдаём за сертифицированный формат то, что не сверялось с текущей спецификацией банка; перед первым реальным платежом колонки надо сверить один раз (порядок меняется через UI, без правок кода). **Добавлено:** шаблон банка можно загрузить и получить порядок колонок из него, а предпросмотр строится на реальных строках выбранного прогона и перечисляет тех, кого в файл не пустят (нет счёта, неверная длина, нулевая сумма) — раньше это выяснялось уже после выгрузки. **СДЕЛАНО 19.09:** статус Armsoft-коннектора наконец описан честно — в `/compare` строка стала `partial` и получила сноску, объясняющую, что синк идёт в HTTP-API ՀԾ клиента; те же границы формулировок внесены в `battlecards.md` и `gtm-playbook.md`. Остаётся то, что кодом не решается: **сертифицированного коннектора Armsoft/1C у нас нет** и до появления спецификации от вендора он не появится — обещать его нельзя ни на сайте, ни на звонке.
4. **Упаковка кейсов:** 3 публичных «до/после» с цифрами. Локальные конкуренты продают на клиентах-логотипах, у нас этого аргумента нет.

### P1 — усилить дифференциацию (3–6 мес.)

5. ~~**Интеграция с ZKTeco/Suprema**~~ — **СДЕЛАНО 19.09:** реализован приём протокола ADMS (`/iclock/cdata`, `getrequest`, `devicecmd`), терминал привязывается к организации по серийному номеру в настройках входящих интеграций, отметки попадают в тот же журнал и очередь проверки, что и webhook-путь. **Добавлено:** инструкция по подключению — шаги, пункты меню устройства, параметры handshake и диагностика — вынесена в `docs/zkteco-setup.md` и встроена в настройки входящих интеграций. **Осталось:** списка проверенных моделей нет и не будет выдуман — UI вместо матрицы совместимости перечисляет требования к прошивке, которые админ проверяет по меню своего терминала.
6. **Постинг вакансий на staff.am / hh / LinkedIn** — превращает главного incumbent-а из конкурента в канал.
7. ~~**Автоматизация для клиента**~~ — **СДЕЛАНО 19.09, дополнено:** конструктор на `/automation` для админов организации под модулем `automation`; настоящий движок (`lib/workflowEngine.ts` + `automationRunner.ts`), ручной запуск исполняет реальные действия. **Добавлено:** подписка на события (отпуска, найм/увольнение), исполнение задержек через отложенные запуски, единый каталог `lib/workflowActions.ts` — конструктор и раннер читают один список, поэтому UI больше не может обещать то, чего движок не делает. **Добавлено:** 9 из 10 триггеров (тикеты и SLA-эскалация, оценки, испытательный срок), `send_email` через уже подключённый Resend (`convex/emails.ts`), UI параметров действий вместо ручного JSON. **Осталось осознанно:** `update_record` (в конструкторе нет способа указать запись и поле) и триггер `contract_expiring` (нужен обход истекающих договоров) — оба показаны в UI с причиной.
8. **Запланированные отчёты** — cron + Resend: «каждый понедельник в 9:00 отчёт по посещаемости на почту».
9. **Marketplace-уведомления:** Slack/Teams/Google Chat webhook-коннекторы (минимум — исходящие уведомления).
10. **AI как дифференциатор:** авто-саммари откликов, AI-скоринг кандидатов, ответы по политикам на армянском, actionable-рекомендации по оттоку (данные уже есть в `attritionRisk`).
11. **Бенчмаркинг зарплат по армянскому рынку** — данных нет ни у одного конкурента; мы можем собрать их первыми из собственной базы (анонимизированно).

### P2 — масштаб и защита (6–12 мес.)

12. **SOC 2 Type II** — по пути из `docs/soc2-type2-readiness.md`: политики, vendor register, monitoring, квартальный restore-тест, пентест, окно наблюдения 6 мес. Открывает банки, телеком, вузы.
13. **Регион:** Россия/Польша уже в налоговом движке — это дешёвый вход в CIS; далее Грузия и диаспора (ОАЭ/США). Один армянский рынок для роста insufficient.
14. **Партнёрская программа** с бухгалтерами/аудиторами/интеграторами Armsoft и 1C — главный канал в Армении.
15. **On-prem / data residency для консервативных заказчиков** — минимум: документ о местах хранения + опция отдельного региона для Enterprise.
16. **Бренд:** уйти от визуальной вторичности, которую замечают в сравнении с PeopleForce.

### Что НЕ делать

- **Не утверждать, что в Армении нет интегрированных HRIS** — это ложь, которую проверят на втором звонке (см. §2.1).
- Не обещать глобальный payroll/EOR — это Deel; продавать дополнение.
- Не идти в enterprise-закупки до SOC 2.
- Не заходить в разговор с локальными конкурентом первыми с ценой — их прайс не публичен, поле неизвестно.
- Не продавать «58 модулей». Продавать конкретный процесс, который перестанет болеть.
- Не скрывать проигрышные строки в `/compare` — доверие и есть преимущество.

## 8. Одной строкой

Strata — самый глубокий по комплаенсу и самый зрелый по платформе HR-продукт на армянском рынке, но **уже не единственный интегрированный**: локальные Hirebee, List Work, Resalt и Spark.work закрыли широту и мобильность, Armsoft держит зарплатный учёт, OnTime — железо. Выигрышная стратегия — не спорить о количестве модулей, а давить тремя вещами: **армянский финансовый комплаенс + платёжные рельсы**, **enterprise-каркас (SSO/SCIM/API/аудит/GDPR)** и **консолидация вместо 4–5 подписок**. Три условия, без которых ниша не удержится: **нативное мобильное приложение, «последняя миля» зарплаты и SOC 2**.
